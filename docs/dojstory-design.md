# DOJstory 위키 설계 초안

작성일: 2026-10-21 KST  
최종 수정일: 2026-10-22 KST  
상태: 부분 자료 확보 및 사용자 보완 반영, 구현 전  
관련 문서: [필요 정보와 데이터 수집 체크리스트](./dojstory-data-request.md), [구현 계획](./dojstory-implementation-plan.md), [사용자 정정·보완](./dojstory-data/clarifications.md)

따오기에 DOJstory 위키를 추가한다. 장비, 재료, 연구, 조합법, 공장을 연결해 사용자가 목표 아이템을 얻는 방법과 필요한 준비를 따라갈 수 있게 한다. 첫 버전은 확인된 정보를 탐색하는 도감과 가이드이며, 계산 도구는 실제 규칙 확보 후 확장한다.

## 확인된 내용과 미확인 규칙

### 사용자 설명으로 확인된 내용

- DOJstory에는 PS 문제 풀이를 통한 장비·재료 획득과 장비 강화가 있다.
- 연구를 통해 재료의 조합법이 생기는 등 기능이 해금된다.
- 공장에는 자원을 채굴하거나 자원을 생산하는 기능이 있다.
- DLC라는 문제팩에서 문제를 풀고, 상위 15개 난이도를 기준으로 DOJpower를 산정한다.
- 높은 DOJpower가 더 많은 연구의 해금 조건이 된다.
- 자료 제공자는 현재 DOJpower로 모든 연구를 확인할 수는 없다.
- 사용자가 실제 자료를 확보해 제공한다. 임의의 아이템·조합법·수치는 생성하지 않는다.

위 내용은 사용자 설명을 근거로 한다. 확보한 원문 6개와 사용자 보완 자료를 구현 계획에서 연결하며, 같은 항목은 최신 사용자 보완을 우선한다.

### 2026-10-22 사용자 보완으로 확정된 규칙

- 연구의 정식 이름은 기초 가공, 결정 압축, 광학 분리 I이다.
- 연구 조건은 `선행 연구 모두 충족 AND (요구 DOJpower 이상 OR 가치의 증표 착용)`이다.
- 오로라 합성은 오로라 프리즘 제작법을 해금하며, 실제 제작에는 조합법을 별도로 획득해야 한다.
- 광학 분리 I·화학공학은 효과가 없다. 화학공학·광학 분리 II의 기초 과학 연구 키트 10개는 각각 소비 재료다.
- 스타포스 실패 시 하락률은 조건부 확률이다. 10→11성의 시도당 실제 하락률은 45% × 8% = 3.6%다.
- 광산 표의 필요 사용게이지는 XP와 같은 단위다. 확인된 수치는 필요 경험치(XP)로 통일한다.
- AI 여부는 배경에만 표시하고 비배경 장비에는 표시하지 않는다. 미확보 이미지는 추후 보완한다.

### 아직 정하지 않을 게임 규칙

| 항목 | 확인이 필요한 내용 |
| --- | --- |
| DOJpower | 상위 15개 선정 대상, 난이도의 수치 변환, 합산·평균·가중 방식, 15개 미만 처리 |
| 풀이 인정 | 만점·부분 점수·재제출 처리, DLC별 차이, 중복 문제 처리 |
| 연구 | 현재 수집하지 못한 연구의 DOJpower 요구치, 선행 연구, 비용, 시간, 효과 |
| 조합 | 투입량·산출량, 해금 조건, 실행 장소, 시간, 실패 여부 |
| 공장 | 건설·작동 조건, 채굴과 생산의 차이, 주기, 투입량·산출량, 제한 |
| 강화 | 확보하지 못한 장비별 단계 효과·개인 보정·예외. 기본 스타포스 표와 조건부 하락 규칙은 확보됨 |

DOJpower가 연구의 요구 조건이라는 설명만으로 DOJpower가 연구 시 소비된다고 해석하지 않는다. 요구 조건과 소비 비용은 별도 항목이다. 상위 15개라는 사실만으로 산식을 구현하거나 예상 수치를 표시하지 않는다.

## 목표와 범위

첫 버전의 목표는 다음 세 가지다.

1. 장비·재료·자원·연구·조합법·공장을 이름과 분류로 찾는다.
2. 획득처, 해금 조건, 생산 방법, 사용처를 연결해서 확인한다.
3. 정보의 출처·확인일·미확인 범위를 구분한다.

현재는 설계문서·자료 요청서·구현 계획을 정리한 단계다. 실제 화면과 데이터 로더 구현은 후속 작업이며 첫 구현 범위는 구현 계획을 따른다.

초기 구현 범위는 운영자가 관리하는 읽기 전용 위키다. 개인 계정 연동, 인벤토리, 연구 수행, 공장 가동 같은 게임 내 조작과 사용자 자유 편집은 포함하지 않는다. DOJpower 계산기, 자동 성장 추천, 생산 최적화는 관련 규칙 확보 후 별도로 설계한다.

DOJstory에서 연구가 잠겨 있다는 사실과 위키에 정보가 없다는 사실을 구분한다. 확인된 공개 연구 정보는 독자의 DOJpower와 무관하게 읽을 수 있게 한다. 개인별 해금 여부는 계정 데이터가 없는 상태에서 판정하지 않는다.

## 사용자 탐색 흐름

### 처음 시작하는 사용자

시작 가이드에서 DLC 문제 풀이, DOJpower, 연구 해금, 재료·장비 획득의 관계를 읽는다. 정확한 지급·산정 규칙은 확인된 범위만 설명한다.

### 목표 아이템을 찾는 사용자

아이템 검색 → 아이템 상세 → 획득 방법 또는 조합법 → 필요한 연구·공장 → 투입 재료의 획득 방법 순으로 이동한다.

실제 데이터에 있는 관계만 연결한다. 모든 아이템이 연구나 공장을 필요로 한다고 가정하지 않으며, 복수 획득 방법은 나란히 보여준다.

### 연구를 찾는 사용자

연구 목록 → 요구 DOJpower와 선행 조건 → 필요 비용·시간 → 해금되는 조합법이나 기능 → 관련 결과물 순으로 이동한다.

선행 연구는 모두 필수다. 이를 충족한 뒤 요구 DOJpower 이상 또는 가치의 증표 착용 조건도 만족해야 한다. 개인 계정 상태가 없으므로 방문자의 충족 여부를 자동 판정하지 않는다.

## 정보 구조와 페이지

기존 상단 메뉴에 DOJstory를 추가한다. DOJstory 내부 메뉴에는 아이템, 연구, 조합법, 공장, 가이드와 변경 기록을 둔다.

| 주소 | 역할 |
| --- | --- |
| `/dojstory` | 통합 검색, 시작 가이드, 도감 바로가기, 최근 변경 사항 |
| `/dojstory/items` | 장비·재료·자원 공통 도감, 실제 분류에 따른 필터 |
| `/dojstory/items/[slug]` | 아이템 상세, 획득처, 생산 방법, 사용처, 장비 강화 정보 |
| `/dojstory/research` | 연구 목록, 확인된 요구 DOJpower·분류별 탐색 |
| `/dojstory/research/[slug]` | 연구 조건·비용·시간·효과, 선행·후속 연결 |
| `/dojstory/recipes` | 결과물·투입 재료로 찾는 조합법 목록 |
| `/dojstory/recipes/[slug]` | 투입량·산출량, 해금 조건, 실행 방법 |
| `/dojstory/factories` | 공장 목록, 확인된 역할별 탐색 |
| `/dojstory/factories/[slug]` | 건설·해금 조건, 채굴·생산 규칙과 관련 자원 |
| `/dojstory/guides/[slug]` | 시작, DLC와 DOJpower, 연구, 강화 등 설명형 가이드 |
| `/dojstory/updates` | 게임 변경에 따른 데이터 수정과 위키 변경 기록 |

이전 초안의 장비·재료 개별 주소 대신 공통 아이템 주소를 채택한다. 장비·재료·자원 경계를 실제 데이터에 맞춰 다룰 수 있고 검색과 참조를 통일할 수 있다. 화면에서는 분류 탭과 필터로 나눠 보여준다. 이 주소들은 아직 구현되지 않았다.

### 화면 원칙

- 기존 따오기의 카드·배지·버튼과 Tailwind 스타일을 재사용한다.
- 이름과 조건을 읽기 쉽게 배치하고, 분류는 색상과 텍스트를 함께 사용한다.
- 상세 정보는 모바일과 키보드에서도 접근할 수 있게 한다. 호버에만 정보를 두지 않는다.
- 긴 표는 작은 화면에서 스크롤하거나 항목별 카드로 읽을 수 있게 한다.
- 이미지가 없으면 이름과 기본 표시를 사용한다. 실제 게임 이미지처럼 보이는 대체 자산은 생성하지 않는다.
- 검색 결과 없음, 없는 문서, 자료 수집 중, 데이터 읽기 실패를 구분한다.
- 일부만 확보된 목록은 전체 개수나 완전한 목록으로 표시하지 않는다.

## 데이터 모델

### 공통 구조

게임 내부 ID가 제공되면 보존한다. 위키의 안정적인 ID와 URL용 slug는 별도로 관리할 수 있다. 표시 이름이 바뀌어도 ID 연결을 유지하며, 공개된 URL을 변경할 때는 이전 주소를 연결한다.

각 항목에 이름, 분류, 설명, 출처 참조, 확인일, 자료 기준 버전 또는 시점, 수집 상태를 둔다. 게임 버전이 보이지 않으면 확인 시각을 남기고 버전을 지어내지 않는다.

확인 상태는 최소한 다음 의미를 구분한다.

| 상태 | 의미 |
| --- | --- |
| 확인됨 | 실제 화면·공식 설명·출처로 값을 확인함 |
| 미확인 | 값이나 기능 존재 여부를 아직 확인하지 못함 |
| 해당 없음 | 이 대상에 해당 항목이 없다고 확인함 |
| 자료 충돌 | 출처 간 값이 달라 추가 확인이 필요함 |

값과 확인 상태를 함께 관리한다. 항목 전체의 수집 상태만으로 개별 필드가 모두 확인되었다고 간주하지 않는다. 미확인 값을 0, 빈 배열, false 등 실제 의미가 있는 값으로 대체하지 않는다.

숫자에는 단위를 명시한다. 시간 단위나 수량 기준이 불분명하면 원문을 보존하고 수치 변환을 보류한다. 출처는 웹 링크뿐 아니라 제공받은 텍스트·이미지 파일과 해당 위치를 가리킬 수 있다.

### 엔터티

| 엔터티 | 핵심 내용과 관계 |
| --- | --- |
| 아이템 | 장비·재료·자원 등 실제 분류, 능력치, 확인된 획득 방법 |
| 연구 | 요구 DOJpower, 선행 조건, 비용, 시간, 해금·변경 효과 |
| 조합법 | 투입 아이템·수량, 결과 아이템·수량, 해금 조건, 실행 조건 |
| 공장 | 건설 조건·비용, 채굴·생산 방식, 가능한 작업과 제한 |
| 공장 작업 | 공장이 수행하는 작업별 투입·산출·주기, 연결된 조합법이 있으면 참조 |
| 강화 규칙 | 적용 대상, 단계별 비용·재료·효과, 확인된 성공·실패 규칙 |
| 획득 방법 | 대상 아이템, 방법, 조건, 수량·확률이 공개된 경우 그 값 |
| 가이드 | 설명 본문, 관련 엔터티, 출처와 확인일 |
| 출처 | 원문·자료 위치, 제공 방식, 확인일, 기준 버전·시점 |

조합법과 공장 작업을 같은 것으로 단정하지 않는다. 공장이 조합법을 실행하는 구조라면 연결하고, 별도 방식이면 각 원문 규칙을 보존한다.

연구의 효과도 조합법 해금에 한정하지 않는다. 실제로 확인된 공장 해금이나 수치 변경 등의 효과가 있다면 대상과 함께 기록한다.

### 관계와 역방향 조회

재료의 사용처는 연구 비용·조합 재료·공장 비용·강화 재료의 참조를 모아 생성한다. 연구로 해금되는 조합법과 결과물도 같은 관계에서 조회한다. 설명문에 이름을 적는 것과 구조화된 참조를 중복 관리하지 않는다.

원문에 대상 이름만 보이고 상세가 잠겨 있으면 출처가 있는 최소 항목으로 기록할 수 있다. 전혀 보이지 않는 대상은 생성하지 않는다. 최소 항목으로 연결된 화면에는 상세 정보 수집 중임을 표시한다.

완전히 확보되지 않은 자료에서는 선행 조건과 연결이 비어 있다는 이유만으로 조건이 없다고 해석하지 않는다. 관계의 확인 상태도 관리한다.

## 파일과 구현 구조

현재 프로젝트는 Next.js 16.3.0, React 19, TypeScript, Tailwind CSS 4를 사용하며 기존 분석 화면도 로컬 파일을 읽는다. 첫 위키는 이 방식을 이어간다.

| 위치 | 역할 |
| --- | --- |
| `src/app/dojstory` | 라우트와 공통 위키 레이아웃 |
| `src/features/dojstory/model` | 데이터 타입과 확인 상태 |
| `src/features/dojstory/data` | 파일 읽기, 검증, 관계·검색용 데이터 구성 |
| `src/features/dojstory/components` | 도감 목록, 상세, 조건·재료 표시, 검색·필터 |
| `data/dojstory` | 실제 자료에서 정리한 JSON과 출처 목록 |
| `data/dojstory/guides` | 운영자가 작성한 Markdown 가이드 |
| `data/dojstory/sources` | 제공받은 원문 자료 중 저장소에서 관리하기로 한 자료 |
| `public/dojstory` | 화면에 표시할 실제 이미지 자산 |

위 경로는 후속 구현 시 만들며, 설계 단계에서 임의 데이터 파일을 채우지 않는다.

서버에서 파일을 읽고 검증한 뒤 페이지 데이터를 구성한다. 검색·필터·정렬 같은 상호작용에 클라이언트 기능을 사용한다. 초기 검색은 이름·별칭·분류를 대상으로 하며 조건을 URL에 남긴다. 목록이 커지기 전에는 별도 검색 서버와 데이터베이스를 도입하지 않는다.

Markdown 렌더러는 구현 시 추가한다. 설치된 Next.js의 `node_modules/next/dist/docs/`에서 관련 가이드를 다시 확인한 뒤 코드와 설정을 작성한다. 페이지별 제목·설명을 제공하고 공개 가능한 상세 페이지를 검색 가능한 형태로 렌더링한다.

자료 제공자가 현재 화면에서 볼 수 있는 정보만으로 시작할 수 있게 한다. 잠긴 연구 전체를 확보해야 구현을 시작할 수 있는 구조로 만들지 않는다. 공개 API 또는 별도 데이터 제공 방식의 DOJstory 지원 여부는 연동을 추진할 때 확인한다.

## 업데이트와 운영

수집 자료 → 필드와 출처 정리 → 구조·참조 검증 → 변경 검토 → 배포 순서로 반영한다. 자료가 업데이트되면 관련 엔터티와 역방향 사용처를 함께 갱신한다.

과거 값과 현재 값이 충돌하면 기준 시점과 변경 근거를 먼저 확인한다. 미해결 충돌은 현재 확정 수치로 표시하지 않는다. 화면에는 마지막 확인일을 표시하고, 게임 변경과 단순 오탈자 수정을 변경 기록에서 구분한다.

공장 도감의 산출량은 기본 규칙인지, 특정 계정의 연구·레벨·효과가 적용된 결과인지 구분한다. 개인 화면의 숫자를 모든 사용자에게 적용되는 기본값으로 등록하지 않는다.

## 단계별 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1. 자료 확보 | 전체 메뉴와 실제 연결 사례 수집 | 보이는 값·잠긴 정보·추가 확인 항목이 구분됨 |
| 2. 모델 확정 | 확보 자료에 맞춰 타입·관계·검증 정의 | 없는 규칙을 가정하지 않고 사례를 표현할 수 있음 |
| 3. 첫 위키 | 홈, 공통 아이템 도감, 연구·조합법·공장 도감, 기본 가이드 | 실제 사례의 획득·해금·생산·사용처를 양방향으로 탐색 가능 |
| 4. 자료 확장 | 데이터 추가, 분류 필터, 변경 기록 개선 | 부분 수집 상태를 유지하면서 새 자료를 반영 가능 |
| 5. 계산 도구 | 확인된 규칙에 한해 비용·재료·시간 계산 | 산식·단위·적용 조건·버전과 검증 사례를 확보함 |

3단계에서 자료가 없는 도감은 자료 수집 중 상태를 제공한다. 공개한 사례의 연결 흐름이 실제 자료로 확인되어야 하며, 모든 게임 콘텐츠 확보가 완료 조건은 아니다.

## 후속 구현 검증

- 데이터: 중복 ID·slug, 잘못된 단위·수치, 확인 상태 누락, 참조 무결성을 검사한다.
- 관계: 실제 사례로 연구 해금, 투입·산출, 획득처, 역방향 사용처를 확인한다.
- 미확인 처리: 잠긴 정보가 조건 없음·비용 0으로 표시되지 않는지 확인한다.
- 화면: 검색·필터·공유 URL, 모바일·키보드 탐색, 빈 결과·없는 문서·읽기 실패를 확인한다.
- 회귀: 기존 유저·대회 분석 진입과 주요 메뉴를 확인한다.
- 코드 검증: 구현 변경에 맞는 테스트와 lint, TypeScript 검사, 빌드를 수행한다.

필수 게임 규칙이 미확인인 계산은 제공하지 않는다. 현재 위키 자료만으로 사용자의 DOJpower와 연구 해금 가능 여부를 추정하지 않는다.

## 후속 구현자에게 맡기는 선택

정확한 컴포넌트 분할, Markdown 렌더러 선택, 파일 분할 단위, 초기 정렬·표시 개수는 확보한 실제 자료와 기존 UI에 맞춰 정한다. 이 선택으로 게임 규칙이나 데이터 값을 새로 만들어서는 안 된다.

데이터 수집의 우선순위와 제출 양식은 [자료 수집 체크리스트](./dojstory-data-request.md)를 따른다.
