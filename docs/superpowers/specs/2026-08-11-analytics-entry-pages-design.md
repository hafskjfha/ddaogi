# 따오기 분석 진입 페이지 설계

## 목표

현재 `/`에서 지원 유저 상세 화면으로 즉시 이동하는 흐름을 서비스 소개와 주의사항을 제공하는 홈으로 바꾼다. 유저 분석과 대회 분석에는 각각 별도의 탐색 화면을 두고, 현재 제공되는 목 데이터 범위 안에서 상세 데모로 이동할 수 있게 한다.

## 범위

- `/` 홈 소개 페이지
- `/users` 유저 검색 및 지원 프로필 안내 페이지
- `/contests` 대회 목록 페이지
- 공통 헤더의 목적지 변경
- 위 흐름을 검증하는 컴포넌트·페이지 테스트

기존 `/users/jtw7913` 유저 상세 페이지와 `/contests/doj-beginner-contest-4` 대회 상세 페이지의 분석 기능은 변경하지 않는다.

## 라우팅과 탐색

| 경로 | 역할 | 주요 이동 대상 |
| --- | --- | --- |
| `/` | 서비스 소개, 주의사항, 데모 진입 | 두 상세 데모 페이지 |
| `/users` | 제한된 유저 검색과 지원 프로필 안내 | `/users/jtw7913` |
| `/users/jtw7913` | 기존 유저 분석 상세 | 기존 동작 유지 |
| `/contests` | 페이지당 20개인 대회 목록 | `/contests/doj-beginner-contest-4` |
| `/contests/doj-beginner-contest-4` | 기존 대회 분석 상세 | 기존 동작 유지 |

공통 헤더의 따오기 브랜드 링크는 `/`, 유저 분석 링크는 `/users`, 대회 분석 링크는 `/contests`를 가리킨다. 페이지 이동에는 설치된 Next.js 16.3의 App Router와 `next/link`를 사용한다.

## 홈 페이지

홈은 기존 리다이렉트를 제거하고 다음 순서의 정적 콘텐츠를 렌더링한다.

1. 따오기를 DOJ 유저와 대회를 분석하는 서드파티 서비스로 소개하는 히어로 영역
2. 유저 분석 및 대회 분석 상세 데모로 바로 이동하는 두 개의 행동 링크
3. 공식 사이트가 아니라는 점과 데이터 시점을 알리는 주의사항 영역
4. 두 분석 기능이 제공하는 내용을 짧게 설명하는 기능 카드

주의사항에는 다음 의미가 명확히 포함되어야 한다.

- 따오기는 DOJ에서 운영하는 공식 사이트가 아니라 유저가 만든 자작 사이트다.
- 표시되는 데이터는 실시간이 아니다.
- 데이터 기준 시점은 `2026.08.11 오전 2시`다.

데모 링크는 중간 탐색 화면이 아니라 사용자가 요청한 상세 데모로 직접 이동한다. 유저 분석 데모는 `/users/jtw7913`, 대회 분석 데모는 `/contests/doj-beginner-contest-4`를 사용한다.

## 유저 분석 진입 페이지

`/users`에는 검색 입력창, 제출 버튼, 지원 프로필 카드가 있다.

- 검색 문자열의 앞뒤 공백은 제거하고 대소문자를 구분하지 않고 `jtw7913`과 비교한다.
- 유효한 검색은 `/users/jtw7913`으로 이동한다.
- 다른 값이나 빈 값은 상세 404로 보내지 않고, 현재 `jtw7913`만 검색할 수 있다는 인라인 오류를 표시한다.
- 검색 오류는 입력과 연결되고 보조 기술에서 인식할 수 있어야 한다.
- 검색창 아래의 지원 프로필 카드는 `jtw7913`이 현재 이용 가능한 데모임을 알리고 상세 분석 링크를 제공한다.

검색 상호작용만 작은 Client Component로 분리하고, 페이지의 설명과 프로필 안내는 가능한 한 Server Component로 유지한다.

## 대회 분석 진입 페이지

`/contests`는 대회 데이터 배열을 페이지당 20개씩 보여주는 목록 구조를 사용한다. 현재 데이터 배열에는 `DOJ Beginner Contest 4` 한 건만 포함하며 이 항목만 상세 페이지 링크를 가진다.

- 각 항목은 대회명과 현재 데이터에서 안정적으로 제공할 수 있는 기본 정보를 표시한다.
- 목록의 페이지 크기는 상수 `20`으로 정의해 이후 데이터가 늘어날 때 같은 UI를 재사용한다.
- 현재는 총 한 페이지이므로 이전·다음 이동은 비활성 상태로 표시한다.
- 페이지 상태는 향후 `searchParams` 기반 페이지 이동으로 확장할 수 있도록 목록 계산과 UI를 분리한다.

가짜 대회나 링크가 없는 자리 채우기 항목은 만들지 않는다.

## 컴포넌트 경계

- 홈은 콘텐츠 중심의 페이지 컴포넌트로 구성하고 기존 `Card`, `Button` 스타일을 재사용한다.
- 유저 검색 폼은 입력 상태, 유효성 검사, 이동만 담당한다.
- 지원 프로필 카드는 지원 계정 안내와 링크만 담당한다.
- 대회 목록은 전달받은 대회 요약 배열을 최대 20개씩 렌더링한다.
- 페이지네이션은 현재 페이지, 전체 페이지 수, 이동 가능 여부를 표현한다.

새 컴포넌트는 PascalCase 파일명을 사용하고 주요 컴포넌트와 함수에 JSDoc을 작성한다. Tailwind CSS와 기존 shadcn 스타일 컴포넌트, `lucide-react` 아이콘을 사용해 현재 분석 상세 화면과 시각 언어를 맞춘다.

## 오류와 접근성

- 유저 검색 오류는 폼 내부에 텍스트로 표시하며 색상에만 의존하지 않는다.
- 모든 링크와 입력에는 명확한 접근 가능한 이름을 제공한다.
- 페이지네이션의 비활성 버튼은 실제 `disabled` 상태로 제공한다.
- 상세 동적 경로의 기존 404, 로딩, 오류 처리는 유지한다.

## 테스트와 검증

테스트는 다음 동작을 확인한다.

- 홈에서 소개, 비공식 사이트 주의사항, 데이터 기준 시점과 두 상세 데모 링크가 보인다.
- 헤더의 브랜드, 유저 분석, 대회 분석 링크가 각각 `/`, `/users`, `/contests`를 가리킨다.
- 유저 검색에서 `jtw7913`은 상세 경로로 이동하고 빈 값과 다른 핸들은 인라인 오류를 표시한다.
- 지원 프로필 카드가 `jtw7913` 상세 링크를 제공한다.
- 대회 목록이 한 건을 표시하고 상세 링크가 정확하며 페이지 크기 20과 비활성 페이지 이동 상태가 반영된다.
- 기존 상세 페이지 테스트가 계속 통과한다.

구현 완료 후 `npm test`, `npm run lint`, `npx tsc --noEmit`, `npm run build`를 실행한다.
