# 프로필 소개와 점수별 예상 레이팅 개선 설계

## 목표

유저 프로필 카드에 DOJ 소개글을 안전하게 표시하고, 사용자 분석의 두 문구를 정리하며, 대회 문제 분석의 고정 25/50/75/100점·중앙값 추정을 실제 점수 분포와 kenkoooo 방식의 확률 모델을 이용하는 추정으로 교체한다.

## 범위

- `data/user_info.md`에 jtw7913의 소개 `PS/CP 초보`를 추가한다.
- 소개는 최대 500자이며 줄바꿈은 최대 6회라는 DOJ 제약을 데이터 파서 경계에서 검증한다.
- 프로필 카드에서 칭호 바로 아래에 소개를 표시하고, 줄바꿈과 긴 문자열을 안전하게 보존한다.
- 사용 언어 분포에서 `custom-json`의 표시 이름을 `기타`로 바꾼다.
- 난이도 분포 범례에서 전체 문제 수를 나타내는 `xx개 중` 보조 문구를 제거한다. 전체 해결 여부 아이콘 계산에는 기존 전체 문제 수를 계속 사용한다.
- 대회 문제 분석의 점수 기준과 예상 레이팅 계산, 도움말, README 설명을 함께 갱신한다.

## 데이터 모델과 경계

`UserProfile`에 직렬화 가능한 `introduction: string`을 추가한다. `parseUserInfo`는 `## 소개` 섹션을 읽어 CRLF를 LF로 정규화한 결과를 반환한다. 빈 소개는 허용하지만, Unicode 코드 포인트 기준 500자를 초과하거나 LF 기준 줄바꿈이 6회를 초과하면 `Invalid user_info.md` 오류를 낸다.

고정 필드로 구성된 `ScoreEstimates`는 다음과 같은 가변 배열로 바꾼다.

```ts
export interface ScoreEstimate {
  readonly score: number;
  readonly rating: number | null;
}

export type ScoreEstimates = readonly ScoreEstimate[];
```

이 구조는 문제마다 실제로 의미 있는 점수 수가 달라도 UI와 데이터 계층이 같은 계약을 사용할 수 있게 한다.

## 점수 기준 선택

문제별 전체 참가자 점수에서 `0 < score < 100`인 부분점수만 오름차순으로 모은다. 이 표본의 25%, 50%, 75% 최근접 순위 사분위값을 선택하고, 중복을 제거한 뒤 100점을 항상 추가하여 오름차순으로 정렬한다.

- 선택된 부분점수는 반드시 실제 참가자가 받은 점수다.
- 0점은 달성 기준으로서 정보가 없어 제외한다.
- 100점은 부분점수 표본이나 만점자 유무와 관계없이 항상 표시한다.
- 부분점수가 없으면 100점만 표시한다.
- 결과는 중복 제거 때문에 문제별 1~4개가 된다.

전체 참가자의 점수를 기준 선택에 쓰되, 레이팅 추정에는 대회 전 레이팅이 제공된 rated 표본만 사용한다. 이 구분은 화면에 보여줄 점수 분포가 전체 대회를 대표하면서도 레이팅 모델에는 신뢰할 수 있는 입력만 들어가게 한다.

## 예상 레이팅 산정

[kenkoooo/AtCoderProblems의 현재 estimator](https://github.com/kenkoooo/AtCoderProblems/blob/main/estimator/main.py)는 사용자 레이팅 `r`과 문제 난이도 `d` 사이의 성공 확률을 다음과 같이 둔다.

```text
P(달성 | r, d) = 1 / (1 + 6^((d - r) / 400))
```

각 선택 점수 `s`에 대해 `problemScore >= s`이면 달성으로 취급한다. `d`를 `[-10000, 10000]`에서 이분 탐색하여 모든 rated 참가자의 예상 달성자 수 합이 실제 달성자 수와 같아지는 지점을 찾고 정수 레이팅으로 반환한다. 이 방식은 달성자 레이팅 중앙값만 보는 대신 달성자와 미달자의 레이팅을 모두 사용한다.

DOJ mock scoreboard에는 kenkoooo가 내부 레이팅 보정에 사용하는 과거 참가 횟수가 없으므로, 원본이 제공하는 대회 전 레이팅을 그대로 모델 입력으로 사용한다. rated 표본이 없거나 실제 달성자가 0명 또는 전원이면 난이도를 유한한 값으로 식별할 수 없으므로 `null`을 반환한다. 점수가 높아질수록 달성자 수가 줄거나 같고 같은 참가자 집합을 사용하므로 별도의 누적 최댓값 보정은 하지 않는다.

## UI

프로필 소개는 칭호 아래에 작은 본문 텍스트로 배치한다. `whitespace-pre-wrap`과 `break-words`를 사용하여 최대 7줄과 긴 토큰이 카드 폭을 깨지 않게 한다. 소개가 빈 문자열이면 빈 요소를 렌더링하지 않는다.

점수별 예상 레이팅 그리드는 `ScoreEstimates`를 순회하여 `xx점`과 예상 레이팅을 표시한다. 고정 4열 전제를 제거하고 1~4개 셀이 현재 열 너비 안에서 균등하게 배치되게 한다. 예상 레이팅 색상은 기존 rating band 표현을 유지하고 `null`은 `-`로 표시한다.

도움말은 다음 두 내용을 짧게 설명한다.

1. 부분점수 분포의 사분위 관측값과 항상 포함되는 100점이 표시 기준이라는 점
2. rated 참가자의 대회 전 레이팅과 달성/미달을 성공확률 곡선에 맞추며, 식별할 수 없는 표본은 `-`라는 점

## 오류 처리

- 잘못된 문제 인덱스는 기존처럼 `RangeError`를 낸다.
- 점수판 파싱 검증은 그대로 유지한다.
- 소개 섹션 누락, 500자 초과, 줄바꿈 6회 초과는 출처 파일명이 포함된 오류를 낸다.
- 동적 점수 기준은 파싱 완료된 0~100 점수만 받으므로 별도의 조용한 보정은 하지 않는다.

## 테스트

- 파서 테스트: jtw7913 소개 파싱, 500자/6회 줄바꿈 경계 허용, 초과 거부
- 프로필 테스트: 칭호 아래 소개 노출, 여러 줄 보존, 빈 소개 미렌더링
- 유저 데이터/컴포넌트 테스트: `custom-json -> 기타`, 난이도 범례에서 분모 문구 제거와 전체 해결 아이콘 유지
- 대회 데이터 테스트: 실제 관측 부분점수 사분위 선택, 100점 강제 포함, 중복 제거, 달성/미달 레이팅을 모두 반영하는 IRT 결과, 식별 불가 시 `null`
- 대회 컴포넌트 테스트: 가변 개수 `xx점` 셀, rating band 색, 새 도움말의 포인터·키보드 접근
- 전체 테스트, ESLint, `tsc --noEmit`, Next.js 빌드를 최종 검증한다.
