# GitHub 방문자용 README 설계

## 목표

GitHub 방문자가 따오기의 성격, 핵심 기능, 기술 구성, 로컬 실행 방법을 짧은 시간 안에 파악할 수 있는 한국어 README를 제공한다.

## 독자와 범위

- 주 독자는 프로젝트를 처음 접한 GitHub 방문자다.
- 따오기가 DOJ의 비공식 서드파티 분석 데모이며 로컬 목 데이터를 사용한다는 점을 명확히 밝힌다.
- 현재 지원하는 유저 및 대회 분석 기능을 세부 구현 파일이나 계산식 없이 요약한다.
- 기여 절차, 배포 절차, 내부 요구사항 추적표는 이번 README 범위에서 제외한다.

## 문서 구성

README는 다음 순서로 구성한다.

1. 프로젝트 이름과 한 문단 소개
2. 주요 기능
3. 기술 스택
4. 시작하기
5. 주요 경로
6. 데이터 안내
7. 비공식 서비스 고지

## 표현 원칙

- 한국어로 작성하며 짧고 직접적인 문장을 사용한다.
- 확인된 기능과 명령만 적고 예정 기능은 포함하지 않는다.
- 데이터 기준 시점은 `2026-08-11 02:00 KST`로 명시한다.
- 실행 순서는 `npm install`, `npm run dev`로 안내하고 기본 접속 주소를 함께 적는다.
- 검증 명령은 `npm test`, `npm run lint`, `npx tsc --noEmit`, `npm run build`로 간단히 묶는다.
- 배지, 스크린샷, 배포 링크처럼 현재 저장소에서 확인되지 않는 요소는 추가하지 않는다.

## 완료 기준

- 기존의 구현 지도와 상세 산식을 제거해 방문자 중심으로 간결해진다.
- 프로젝트 소개, 핵심 기능, 로컬 실행법, 데이터 출처와 비공식 고지가 빠짐없이 포함된다.
- 모든 Markdown 코드 블록과 링크 표기가 올바르다.
- 프로젝트 검증 명령을 실행해 README 변경이 코드 품질 검사를 방해하지 않음을 확인한다.
