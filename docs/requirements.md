\# 따오기 웹사이트 제작 요청사항

사용자는 doj(https://doj.kr/ko)이라는 사이트의 서드파티 웹서비스를 mock 데이터로 만들어 보려고 한다. 사이트 이름은 따오기(ddaogi)이다.

doj는 온라인 저지로, 온라인 대회가 열리며 서브테스크가 존재하는 문제가 많이 출제되는 OJ이다.

또 대회가 종료되면 codeforces,atcoder 처럼 레이팅을 산정하여 레이팅을 주고 랭킹과 레이팅에 따른 칭호(아래에서 설명)를 주는 시스템이 있다.



사용자는 다음 페이지를 만드려고 계획에 있다.

\- 유저 정보 페이지

&#x20;   - 해당 유저의 레이팅/레이팅 변화 그래프, 대회 퍼포/diff, 대회 스트릭를 표시하는 탭

&#x20;   - 해당 유저가 시도했지만 만점을 받은/받지 못한 문제 표시, 문제 풀이 스트릭, 푼문제의 난이도 분포를 표시하는 탭

&#x20;   - 기타 정보: 언어별 제출(전체 제출의 언어 도넛 그래프 등), 대회1등 횟수, 대회 퍼솔 개수, etc 를 표시하는 탭

\- 대회 정보 페이지

&#x20;   - 문제별 난이도(티어/추정 레이팅), 각 문제당 퍼스트 만점, 대회 rated참가자의 4분위수 레이팅, etc



사용자가 원하는 페이지를 만들때 유저 정보 페이지를 완성후 대회 정보 페이지를 제작하려고 한다.

다음에서는 각 페이지 별로 사용자가 원하는 구체적인 사항이다. 구체적인 사항을 읽고 구현을 해야하며, 코드 작성시 규칙섹션은 무조건 지켜야 한다.



\## 유저 정보 페이지

상단에는 유저의 프로필 사진과 장착한 프로필 플랜카드 사진을 표시할수 있게 하며 아래의 내용을 탭으로 구분한다.

\### 레이팅 관련

유저의 레이팅/레이팅 변화 그래프 부분에서는 해당 유저의 현제 레이팅과 max 레이팅을 표시하되 아래의 칭호와 색도 codeforces처럼 보여준다. 색과 칭호는 다음과 같다.



\#### 레이팅별 색과 칭호

\- 0-1199 NEWBIE 회색rgb(100, 116, 139)

\- 1200-1399 PUPIL 연두색(rgb(34, 197, 94))

\- 1400-1599 SPECIALIST 민트색(rgb(20, 184, 166))

\- 1600-1799 EXPERT 파란색(rgb(59, 130, 246))

\- 1800-1999 CANDIDATE\_MASTER 보라색(rgb(139, 92, 246))

\- 2000-2199 MASTER 오랜지색(rgb(249, 115, 22))

\- 2200-2399 INTERNATIONAL\_MASTER 붉은색(rgb(239, 68, 68))

\- 2400-INF GRANDMASTER 진한 붉은색(rgb(220, 38, 38))



또한 현재의 레이팅 랭킹(xx등,top yy.y%)를 표시하게하고 아래쪽에는 rated대회에 참가하여 얻거나 잃은 레이팅을 꺾은선 그래프로 표시한다. 단 칭호구간에 맞게 그래프의 y축에 따른 배경색은 레이팅별 색과 칭호에 맞게 구현한다. 또 꺾은선 그래프의 점에 마우스를 올렸을때는 적절한 위치에 해당 대회의 이름과 날짜, 해당 대회후 레이팅과 diff레이팅, 해당 대회에서의 순위를 표시한다.



그리고 참가했던 모든 대회의 날짜, 대회이름, 랭킹, 퍼포먼스 레이팅, diff 레이팅, 티어 변화을 리스트 형식으로 최신순으로 나열되게 하는 표시를 한다. 다만 unrated 인경우 퍼포먼스레이팅과 레이팅 diff를 -로 표시하고 티어 변화가 없는 경우에도 -를 표시한다.

퍼포먼스 레이팅을 꺾은선 그래프로도 볼수 있게 기능을 만든다.



대회스트릭은 doj에서 열었던 모든 대회의 개최일을 기준으로 해서 좌표압축을 했을떄(즉 첫번째 대회는 1, 두번째 대회는 2,...) 해당 대회에 참가했다면 초록색 잔디로 표시하게 하는 스트릭을 만드는 것이다. 현재 만들어지고 있는 연속 스트릭 날짜와 최장 연속 스트릭도 표시한다.



\### 문제 관련

해당 유저가 1번 이상 제출한 문제에 대하여 해당 문제를 만점을 받은 경우와 만점을 받지 못한 문제로 나눈다. 각각 표시할때 문제의 난이도를 티어이름 첫글자+난이도 숫자(ex. Silver V->S5)와 문제 제목(길면 ...으로 자르기, 호버시 풀제목, 클릭시 해당 문제 https://doj.kr/ko/problems/<id> 로 리다이액션)을 표시한다. 만점을 받지 못한 문제는 호버시에 풀 문제제목 밑에 받은점수/만점을 표시할수 있게 한다.

문제 풀이 스트릭은 유명하니까 설명을 생략하고 푼문제(만점을 받은 문제)의 난이도 분포를 표시에서는 원형 그래프로 U,B/S/G/P/D/R(언레이티드/브론즈/실버/골드/플레티넘/다이아/루비)로 표시하되 자세히 버튼을 누르면 자세한 그래프(세부 난이도 표시)로 전환한다. 원형 그래프 옆에는 각 티어별 문제해결수와 전체 해결한 문제수에서 해결수(%)를 표시한다. 또한 해당 난이도의 모든 문제를 풀었다면 푼 문제수 옆에 초록색으로 표시한다. 그리고 총 만점을 받은 문제수도 표시하고 이를 기준으로 한 랭킹도 표시한다,



\### 기타 정보 관련

&#x20;언어별 제출(전체 제출의 언어 도넛 그래프 등), 대회1등 횟수, 대회 퍼솔 개수를 표시하는 탭을 적절하게 만든다.





\## 대회 정보 페이지

대회 정보 페이지에서는 대회의 문제별 난이도(doj에서 유저 투표로 제공되는 난이도, U,B/S/G/P/D/R(언레이티드/브론즈/실버/골드/플레티넘/다이아/루비))와 해당 문제의 25%,50%,75%,100%의 점수를 받을수 있는 예상 레이팅을 표시하고 각 문제의 퍼스트 만점(First Full score,FF)의 닉네임도 표시하게 한다.

대회 rated참가자의 4분위수 레이팅도 적절하게 표시하는 UI를 만든다.

참고로 대회 참가 타입은 일반/window가 있으며 일반은 codeforces/atcoder과 같은 방식이며 window는 대회가 열려있는 시간 중 원하는 시간에 시작하여 대회규정시간만큼 응시할수 있는 방식이다.



\## \*\*코드 작성시 규칙(필수 무조건 지켜야 함)\*\*

\- 디자인은 모던한 스타일로 만든다.

\- 코드는 react+nextjs를 사용하여 작성하되 css는 tailwind를 사용하며 피할 수 없는 경우에만 style을 직접 사용한다.

\- 다크모드는 tailwind의 dark: 부분을 사용하되 대부분은 기본 dark: 에 맞춰 특수한경우 외엔 작성하지 않아도 된다.

\- 코드는 SoC원칙을 준수해야한다.

\- 디자인부분은 shadcn, lucide-react를 적극 이용하여 디자인이 일관되게 코드를 작성한다.

\- 코드 작성후 lint검사 tsc의 noEmit을 이용한 타입검사를 한다.

\- 타입은 가급적이면 unknow, any를 사용하지 않는다.

\- 컴포넌트 파일은 파스칼 케이스로 작성한다. 하지만 라우터이름은 케밥케이스를 사용한다.

\- 주요 함수/컴포넌트에 jsdoc주석을 작성한다.



\## 기타

doj는 형식 공식적인 api가 없기 떄문에 사용자가 직접 mock데이터를 만들었다.

데이터들은 data/폴더 안에 있으며, mock데이터로 페이지에 표시될 유저의 핸들은 jtw7913이다.

또한 코드작성중 요구사항에 대한 모호함등은 질문해도 좋지만 코드나 개발의 제작 방향은 묻지 말고 바로 추천하는 방향으로 작성하면 된다. 또한 외부 라이브러리가 필요하다면(UI, 유틸리티 등) 그냥 설치해도 된다.

data/result.json은 jtw7913이 제출한 기록을 모두 기록한것이며, difficulty.json은 해결한 문제들에 대한 난이도, user\_info.md는 jtw7913의 정보, contest\_info.md는 DOJ Beginner Contest 4의 정보이다.
